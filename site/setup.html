Co jest potrzebne,
żeby Flexa działała.

Landing i dokumentacja są statyczne. Konta, dane i aplikacja wymagają skonfigurowanych usług — nie udajemy, że samo GitHub Pages jest backendem.

Podział hostingu

GitHub Pages: ta strona i dokumentacja, docelowo flexa.click. Cloudflare Pages: aplikacja, docelowo app.flexa.click. Supabase: konta, prywatna baza Postgres i funkcje do wyszukiwania produktów oraz usuwania konta.

Co jest zaimplementowane

Rejestracja i logowanie, profil i cele, dziennik kalorii i makro, woda, produkty własne, skaner, ręczne treningi, import GPX/TCX, analizy 7/30/90 dni, pomiary, eksport i usuwanie konta. Tryb demo jest oddzielny i lokalny.

Nie ma zdjęciowego AI, społeczności, segmentów Stravy, nawigacji tras ani natywnego Apple Health/Health Connect. Integracja API Stravy jest wyłączona z uwagi na zakaz aplikacji konkurujących z jej funkcjami.

Jak uruchomić

Dokładne kroki są w instrukcji wdrożenia. Lokalnie potrzebujesz Node.js, npm ci i npm run dev. Demo nie wymaga kluczy. Konta wymagają projektu Supabase, migracji SQL, wdrożenia dwóch funkcji, ustawienia SMTP i informacji o administratorze prywatności.

Ta strona nie tworzy zewnętrznych kont, nie kupuje domeny i nie ustawia DNS. Link do działającej aplikacji właściciel włącza przez zmienną repozytorium FLEXA_APP_URL po konfiguracji usług.

Nie pomijaj przed publicznym startem

Wybierz region bazy, uzupełnij administratora i kontakt prywatności, skonfiguruj retencję i kopie, zweryfikuj domeny oraz wykonaj próbę dwóch kont. Przejrzyj obowiązki RODO dla danych zdrowotnych. To opis techniczny, nie certyfikat zgodności prawnej.

Research zweryfikowany w źródłach oficjalnych 6 października 2026. Limity usług i regulaminy mogą się zmieniać.
